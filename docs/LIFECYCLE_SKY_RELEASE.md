# Lifecycle and radial sky candidate

Based on user-verified commit f970e3d. Native transport, HTTP scheduling, neural
weights, organism movement, lake geometry and Glass surface code are unchanged.
This branch is a review candidate, not a claim of completed Studio visual acceptance.

## Resource ownership and removal

Living plants own reserves, funded construction jobs and attached organs. Shedding
or organ failure transfers structural carbon exactly once into soil litter. Litter
owns its associated nutrient fraction and decomposes independently of visual LOD.
Death refunds pending construction before moving structural biomass into litter,
mobile carbon into a separate dissolved pool, and free nutrients/water into soil.
The existing decomposition rates apply to the two pools. Respired carbon returns
through the existing C++ atmospheric binding. Removing a Roblox model has no write
path into this accounting.

Dead organs and standing dead plants leave the organism renderer. Grounded litter
uses the terrain raycast path, cannot be selected as a living organism, and uses a
bounded 128-part visual budget. Cells outside that budget retain all their biomass.
Destroyed microbial and plant selection targets clear their selection identifier.
Existing microbial chemistry recycling and detail-rig release remain intact.

Death history is checkpointed independently: organism ID, lineage, species, age,
death step and carbon at death. Legacy bodies already dead on import use zero
for unknown death age/time rather than inventing a historical date. It is not counted again as biomass. Records already
removed by an older executable cannot be recovered retroactively. History is kept
in the checkpoint, with a one-million-record parser limit and the existing 64 MiB
plant checkpoint budget; planetary-scale historical storage will need archival
segmentation before approaching that bound.

The new executable reads CIPLANTS1 and writes CIPLANTS2. The legacy pending-growth
fixture was generated by the unchanged baseline implementation. Backward reading,
continued deterministic replay, pending-job cancellation, starvation death,
shedding, removal and complete litter decomposition are tested. Older executables
cannot read the new format: retain the original runtime/checkpoint for rollback.

## Tree evidence, including the failed requirement

Two assays use five seeds, up to 130,000 plant steps, a 200-step day/night cycle,
and conserved resources. The cultivation assay retains eight individuals and
turns excess seeds into dead biomass; this is an explicitly controlled experiment,
not validation of a whole-lake food web. Atmospheric carbon is not limiting in the
standalone assay. Mechanical founders start as seeds. Neural founders use the
same initial root/stem/two-leaf phenotype and random-weight initialization as the
planet's tree type.

Mechanical policy results: all five runs retained living descendants after
130,000 steps; 29–87 individuals established and reached the maturity threshold
per run. Peak height was 6.64–7.93 studs. Birth counts include excess seeds that
were thinned, so they must not be read as establishment counts.

Neural policy results: none of the five runs produced offspring. Lifetimes ranged
from 198 to 114,921 steps. One grew to 12.06 studs, while the others peaked at the
initial 4.2-stud leaf height. This fails a sustained neural-tree population
requirement. It does not establish a universal carbon shortage, nor justify
extending all lifespans. No lifespan, maintenance, seed cost or neural weights were
changed. Type 0 remains a separate short-lived type, not a tree model.

Next biological work requires policy-level investigation/training and a full
chemistry-bound ensemble, with explicit provenance for any authored starting
controller. Mechanical-policy success must not be described as evolved neural
success. Reproduce the assays with the tree_lifetime target; no arguments selects
mechanical policy, --neural selects random neural founders.

## Sky ownership and remaining visual gate

The lake controller previously overrode above-water atmosphere and lighting based
on proximity. It now publishes actual lake submersion blend and owns underwater
presentation. The celestial controller owns above-water sky/lighting and uses
canonical sun direction plus the camera's current planetary radial up vector.

RadialSky computes all six sky faces from one continuous directional color model.
It removes the baked horizontal horizon and suspends conflicting global engine
atmosphere/clouds. It is a procedural presentation approximation, not a full
radiative-transfer solution or a replacement for C++ photosynthesis. Physical sun
and moon objects remain. Engine shadow direction remains an explicitly measured
approximation; Roblox's global lighting system is not an arbitrary spherical sun
vector API.

Six 64x64 EditableImages use about 96 KiB of raw pixels. Directions are cached;
one face is uploaded per scheduled update, respecting the documented display
budget. If image creation/API access fails, the original sky is retained and a
clear diagnostic is reported. Existing Mesh/Image API permission is still needed.

Run tools/studio/SkyDiagnostic.lua in the CLIENT command bar during Play. Compare
CI_PlanetCelestial.DiagnosticMode = Normal, OriginalSky, EngineAtmosphere and
restore Normal. Lighting.CI_DisableWaterPresentation isolates underwater effects;
remove that diagnostic attribute afterwards. The inventory prints other effects.

Mandatory Studio acceptance remains: inspect cube orientation/seams, stars,
reflections, dawn/noon/dusk/night at the lake, equator, pole and opposite hemisphere;
enter/leave the lake; ensure the sky does not jump and only one atmosphere is active.
Record SkyRenderer, LocalUp, SolarDirection, EngineDirectionErrorDegrees,
UnderwaterBlend and client frame time. This environment has no Roblox Studio
renderer, so those observations have NOT been performed here.

## Validation

- All 28 native tests passed (Release, GCC), including native HTTP integration and
  autonomous checkpoint recovery.
- Six headless Luau suites passed, including cube edge continuity and directional
  color bounds across dawn/noon/dusk/night at four planetary positions.
- All active Lua sources compiled with Luau. These checks do not simulate Roblox
  rendering, asset permissions, or Windows/MSVC.
- Native transport implementation and application loop are byte-unchanged from
  the successful repository baseline.

## Safe use

Keep the currently working project/runtime. Build this candidate separately with
scripts/Build.ps1, or the same inline CMake commands used for the native baseline.
Copy your runtime into the candidate only after stopping its simulation, then use
the existing native start command and Rojo workflow. Never run two simulations
against the same runtime. No new world or terrain generation is required.
